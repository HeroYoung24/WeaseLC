## 3. 首批接口契约与审查重点

### 计时策略

- Begin只能成功一次，包括已经End的实例也不能重新启动；重复模型结果应复用同一建议对应的计时对象。
- nowMs由未来宿主传入单调时间；值0有效，时间倒退按失效处理。普通重复/标点不能重置年龄。
- 最长年龄包含排队/隐藏时间；最短时间只累计实际可见区间。到期、接受、拒绝或不安全来源均可终止，最短时间不产生写入权限。
- 实际ShowWindow之前需先调用CanReveal；确认显示/隐藏后调用SetVisible。没有可靠锚点或没有窗口时不得伪报可见。
- End只终止规则对象；UI隐藏、队列移除、终态标记仍须控制器完成。未实现这些接入，不宣称本模块已经处理到期队列。
- 现有started_同时约束来源捕获的寿命。不能简单替换成15秒就声称提示至少3秒；未来须拆开来源、请求、建议时钟并逐次保留原安全校验。
- 此处预设不是自动用户分类，也不保存或采集输入节奏。个性化参考及设置界面均待后续开发。

### 标点等价策略

- InferenceTarget从原InferenceRequest提取同一规则；手动/HostNearby、内部标点、全标点输入保持原样，最后一个标点不同则视图可以不同。
- EquivalentAutomaticInputs仅比较已经通过原请求验证的自动输入。非零session、editingEpoch及完整modelRevision是调用者契约；不是现有IPC中已经提供的新字段。
- editingEpoch须能区分编辑框、来源片段及会话重建；不能拿每次变化的请求编号来替代，也不能把同一进程所有文本共用一个epoch。
- modelRevision必须随相关模型/配置变化失效；同名模型在服务端悄悄换权重仍是原项目的已知限制，此模块未解决该限制。
- 比较故意不要求相同request.version，以识别等价追加；这绝不允许重标旧结果版本。每个接收者仍需基于自己的原始文本重新解析、过滤、映射及TSF核对。
- 不缓存已带旧start/session/version的CheckResult并直接搬给新请求。缓存层待设计；失败或取消不能充当成功no_change。
- 比较不是正文合法性验证或安全授权；空/过长/不同before/after或身份不符直接不合并，原有ValidRequest和受保护场景判断不能删。
