# 本地模型与请求调度（2026-10-15）

本轮仅使用程序内置的合成语料。没有读取真实用户输入、注册或激活测试输入法，也没有连接日常 WeaselServer。测试使用真实 TSF 文本存储、写锁与生产组合提交函数，注入合成响应；它覆盖模型衔接，不能代替键盘 → Rime → 真实应用的安装验收。

## 已完成的流程改进

- `RequestQueue`：输入事件线程持有；默认去抖 250ms，同时最多一个正在执行和一个最新待执行请求。新快照取消旧请求；焦点失效清空待检查项；10 秒后结果不再展示。只合并请求，不猜测两次上屏在文档中相邻，不拼接旧正文。队列已用于独立 TSF 测试桥，尚未接入日常版的自动采集。
- 请求结束使用独立工作令牌；错误会话/版本的响应被拒绝，但仍释放本次工作槽，旧令牌不能结束新任务。空白文本不请求模型。
- WinHTTP 改为异步 I/O，工作线程每 20ms 检查取消和总截止时间，关闭当前请求并等待最后的 `HANDLE_CLOSING` 回调后释放缓冲区。设置窗口仍由后台执行，不在输入线程或 TSF 编辑锁内推理。取消接口依据 [Microsoft WinHTTP 文档](https://learn.microsoft.com/en-us/windows/win32/api/winhttp/nf-winhttp-winhttpclosehandle)。
- 总超时限制覆盖慢速持续返回数据；响应上限 64KiB；有 Content-Length 时核对实际长度，提前断开、过大响应、非成功状态及重定向均不作为纠错结果。
- 默认任务说明改为中文，给出一个与测试语料不同的格式例子；不修改模型权重。
- 模型分数不能绕过确定性的文本保护：代码块、ASCII 标识符/数字/邮箱、网址（含中文路径）中的修改被隐藏；原文或替换长于 32 UTF-16 单元、编辑距离大于 2 的改写被隐藏。正常目标中邻近的代码/网址不会阻止其余错字检查。这些规则偏保守，不能识别所有专名，也不能保证建议正确。
- GUI 显示请求耗时，取消提示与保护规则的状态文字已更新；本地/联网设置仍分开，密钥、授权和正文不持久化。

## 可复现的本地部署

文件保存在 `E:\WeaseLC\local-model`，与源码和日常输入法安装目录分开。下载脚本固定模型提交号和运行时版本，先校验 SHA256 再使用。部署仅为手动进程，没有服务、计划任务或开机启动项。

| 项目 | 选择 |

| GPU | RTX 4060 Laptop，8188MiB；运行时设备 Vulkan0 |
| 运行时 | llama.cpp b11640 / 3e390af18，Windows x64 Vulkan，32,159,276 字节压缩包 |

8K 是部署时选择的工作窗口，不是声称模型只能处理 8K。请求限制按 UTF-16 单元计数，目标 1024、前后各 256，与 token 不同；当前超限拒绝，不静默截断或迁移旧文档。长文分块与经核对的文档短期上下文仍待实现。运行时支持本地兼容 HTTP、约束 JSON 与缓存等能力，依据 [llama.cpp 服务说明](https://github.com/ggml-org/llama.cpp/blob/b11640/tools/server/README.md)。

模型来自 [Qwen 官方 1.7B 仓库](https://huggingface.co/Qwen/Qwen3-1.7B-GGUF)与 [Qwen 官方 4B 仓库](https://huggingface.co/Qwen/Qwen3-4B-GGUF)，许可证为 Apache-2.0；运行时为 MIT，见 [运行时许可证](https://github.com/ggml-org/llama.cpp/blob/b11640/LICENSE)。对应许可证文本与文件 SHA256 留在部署目录；分发时须保留各自许可证和声明，项目原有许可证要求仍适用。

## 真实模型实验记录

初始 1.7B 英文任务说明：10 条中 7 条对照文本无误报，但 3 条错字全部漏检；接口/格式均正常。冷请求 5656ms，中位 172ms。

换用中文任务说明后、保护规则加入前：开发样例 3 个错句中修对 2 个，7 条对照中误报 2 个（标识符命名风格、语义改写）；另一组 3 个错句只修对 1 个，5 条对照误报 2 个（标识符、软件名）。热身后的开发样例中位 375ms。这些实测说明“JSON 合法”和较高自评分不能作为语义正确的保证。

### 最终 4B 对照

| 检查 | x64 | Win32 |
| --- | --- | --- |
| 开发语料：3 错句 + 7 对照句 | 87 项通过 | 87 项通过 |
| 另一组：3 错句 + 5 对照句 | 71 项中 2 项质量失败 | 同左 |
| 热身后开发组请求耗时 min / median / max | 250 / 266 / 579ms | 250 / 266 / 578ms |
| 热身后另一组请求耗时 min / median / max | 250 / 266 / 593ms | 250 / 266 / 594ms |
| 未知/密码不提交、结果归属/时效、DLL 卸载 | 通过 | 通过 |
| GUI 实际本地 HTTP：正确文本、错字显示、关闭取消 | 3 项通过 | 3 项通过 |

默认阈值 0.90 下，6 条错句共 4 条显示预期修正，12 条对照句未显示错误建议。开发组修正 `错子→错字`、`文挡→文档`、`解绝→解决`；另一组修正 `阅渎→阅读`。这只是 18 条合成语料，不代表真实准确率，也不证明品牌/人名和指令式文本已经普遍安全。

对另两条未显示建议单独检查了原始合成响应，并用**相同响应**再次调用生产解析器，阈值只在诊断副本中改为 0.80：

- `记绿→记录`：0.85，正确建议，默认阈值隐藏。
- `收倒→收下`：0.85，错误建议；预期是“收到”，默认阈值隐藏。

两种语义结果分数相同，说明不能简单降低阈值追求通过，也不能把自评分当成正确概率。默认值未修改；UI 可自定义，但尚无校准证据。对照日志在部署目录 `threshold-analysis-4b.log`，只含内置合成语料。

第一轮 4B 冷请求曾达到 10 秒超时，接口拒绝展示该过期结果。启动脚本已增加合成 JSON 请求预热，完成后才打印 Ready 并写入带进程号的临时 `ready.json`。已有 GPU 编译缓存下，重启和预热实测 3406ms；这不是全新驱动缓存下的冷启动保证。脚本退出/失败时清理自己启动的子进程；不抢占已占用端口。表中请求耗时包含本机 HTTP、模型和宿主轮询，不含额外 250ms 去抖，不是纯推理耗时。

### 构建与边界回归

- TSF、传统 IME、Server、Deployer 的 Release x64/Win32 构建成功，仍存在原有 `localtime` 等警告。
- 两架构各 90 项离线、9 项真实回环 HTTP、23 项 TSF 模拟回路以及三语言离线 GUI 自检通过。
- 主动 HTTP 取消约 109–125ms；循环取消后的新请求可正常完成；慢速响应在 2 秒总截止时间内终止。
- 正式 GUI 的自动时机、提示位置等仍是预留项；本轮仅手动检查和独立 TSF 诊断回路。正式自动进程/IPC 与真实应用验收未完成。

结论：保留 4B Q4 作为手动检查和继续评测的本地基线，不启用日常自动纠错。1.7B Q8 保留为对照；部署目录包含二者、便携运行时、许可证、摘要清单、启动脚本和合成日志。

收尾已完成：停止自有模型/启动器和 Python 模拟服务，18962/18963 无监听，临时 ready/launcher 标记与失败下载残片删除。源码下诊断输出/中间目录、探测 DLL 与测试 EXE 均已清理，复现前须重建；普通构建保留。四个注册表视图没有探测 COM/TIP 根键，输入法列表无测试项，相关 Windows 服务为 0。日常 WeaselServer PID 21288（13:52:14）、搜狗 Broker PID 10764（13:52:07）及原版 COM 路径保持不变。
