## 已确认事实与恢复操作

- 失败版本是隔离 CLSID `{B749B45E-7DCE-4496-8414-9EE10970260A}`、语言配置文件 `{A2F702D2-DD84-4C9E-9C18-66FEBA75C4E3}` 的 v2 DLL；与原版小狼毫的 CLSID 不同。
- v2 注册后，测试配置文件和输入法列表项存在；普通 COM `CoCreateInstance` 能创建测试类。但是，在用户试用后，对记事本及进程模块的检查未发现 v2 DLL 被加载。故障首先表现为 TSF 没有在目标程序里加载测试 DLL，不能把它归因为正文读取代码或模型代码。
- 通过 `register-correction-probe.ps1 -Action Unregister` 撤销了 v2 的输入法列表项和 32/64 位 COM 注册，并清理仅属于测试 CLSID 的 TSF 分类目录残留。随后 `Status` 显示 `Probe64`、`Probe32` 为空，`ProbeTip=False`，`InputMethodListed=False`；对该测试 CLSID 的 `HKLM\SOFTWARE\Microsoft\CTF\TIP` 查询也显示不存在。原版 32/64 位 COM 路径仍为 `C:\windows\SysWow64\weasel.dll` 和 `C:\windows\system32\weasel.dll`。
- 目前原有小狼毫保持正常功能。测试版**未注册**，不得把 v3 编译成功理解为功能已恢复。

## 源码修正与仍待验证的原因

- v2 把测试 COM 类写在 `HKCU\Software\Classes\CLSID`。本机原版 Weasel 的 COM 类在系统级注册，且原版安装程序在注册 TSF 语言配置文件后调用 `EnableLanguageProfile`。v2 注册脚本没有这一步。这两个差异都可能导致“列表项可见、TSF 未加载 DLL”，但目前没有单独实验能断言哪一个是根因。
- v3 源码把**仅测试版**的 COM 注册改到 `HKLM\Software\Classes\CLSID`，并在注册后显式启用简体中文语言配置文件；卸载时禁用它。普通 Weasel 构建的注册逻辑没有改动。
- v3 输出隔离在 `output/Probe/v3/`，x64 和 Win32 Release 编译均成功，只有现有编译警告。**v3 尚未安装、没有真实输入验证。**
- 旧脚本的 `Register` 动作已禁止，以免重复安装已知失效的 v2；`Status` 和 `Unregister` 保留用于核对、清理 v2。不能用该脚本安装 v3。
- 后续清理已删除 `msbuild/Probe/`、实验构建日志及 `output/Probe/` 中的所有文件。早期版 DLL 曾被 ChatGPT 进程占用；应用重启后已删除，`output/Probe/` 整个目录也已移除。测试版无 COM/TSF 注册，不在输入法列表中。

## 下一次排查的顺序

本轮继续排查已修正一个明确的语言栏问题：原测试构建把 `GUID_LBI_INPUTMODE` 改成自定义 GUID；现已恢复 Windows 标准值 `{2C77A81E-41CC-4178-A3A7-5F8A987568E6}`。[Microsoft 文档](https://learn.microsoft.com/en-us/windows/win32/api/ctfutb/ns-ctfutb-tf_langbariteminfo)说明 Windows 8 起使用其他值的模式项会被忽略。这会影响按钮与菜单显示，但还没有证明它是不能输入中文或目标应用未加载 DLL 的原因。

新增 [`test/ProbeActivation`](../test/ProbeActivation/README.md) 的独立诊断源码，默认检查 DLL 加载、类创建、三种语言的探测菜单资源以及两枚图标；当前 x64 默认检查退出码 0。测试版另加入只在本进程保存的激活阶段与按键事件注册 HRESULT。手动激活停在阶段 2：`ActivateEx=0x80004005`、`AdviseKeyEventSink=0x80070057`（`E_INVALIDARG`）；原有正常工作的系统 DLL 在同类手动激活尝试中也失败，因此这不是有效的真实输入验收，也不能据此宣布根因已解决。普通 x64/Win32 TSF 回归编译均通过。整个诊断过程没有注册测试输入法或 Windows 服务，生成的实验二进制与中间文件在本轮结束时清理。

### 初始化失败的清理修正

继续排查发现：原退出路径会取消未成功注册的按键监听；线程焦点监听的取消函数没有被调用；未激活或重复退出可能解引用空线程管理器。现已补上按键监听注册标记、线程焦点监听取消与 cookie 重置、无效激活参数检查、重复激活及重复退出保护，并初始化 ClientId 和激活标志。

独立诊断增加模拟线程管理器，不建立系统 TSF 激活或 IPC 会话。线程事件注册失败、按键管理接口不可用、按键监听注册失败三种场景均通过；每种场景两次失败后再次激活、每次重复退出，确认无多余按键取消、线程监听释放、线程管理器引用回到基线。资源检查与这些测试总体退出码 0，普通 x64/Win32 TSF 编译均通过。成功激活后的线程焦点监听清理仍需运行验证。这些清理问题**尚未证实与原中文输入故障直接相关**。

后续还需检查 compartment 注册失败和文本布局监听的清理路径；目前模拟测试只覆盖激活早期失败，不能覆盖后续所有阶段。

本轮收尾核对：`output/Probe/`、`msbuild/Probe/`、`output/ProbeDiagnostics/`、`msbuild/ProbeDiagnostics/` 均已删除；32/64 位 HKLM/HKCU 的测试 COM 和 TIP 根键均不存在，测试配置文件不在输入法列表中。未发现相关 Windows 服务注册或残留诊断进程。原版 COM 路径仍指向两份系统目录 DLL，原版 `WeaselServer.exe` 仍从 `C:\Program Files\Rime\weasel-0.17.0\` 运行。本轮没有安装或重启原版输入服务，也没有实际按键验收。
