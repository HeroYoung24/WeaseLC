## 2. P0-1：建议身份、生命周期和按键

### 身份与状态

- [ ] 区分输入会话、请求版本和建议身份。模型重复响应或请求编号变化，不得让同一建议变成新提示。
- [ ] 建议身份至少关联编辑上下文、具体原文范围、原词/替换及必要的语境；不能仅凭错词字符串去重，不合并不同位置的相同错词。
- [ ] 定义待检查、等待展示、正在展示、应用并确认、已拒绝、已到期、来源失效等状态；所有异步结果经过同一入口更新。
- [ ] 同一会话的已接受/已拒绝/已到期建议留有界短期处理标记。等价响应不得复活该项；超出容量、会话结束即清理，不生成永久词条。
- [ ] 新语境下再次出现相同词，不等于旧项复活。只有重新确认的来源才可建立新建议；连续追加标点、重复响应不能作为绕过处理标记的理由。

### Tab与Esc

- [ ] 每条建议最多一次成功采纳；一个完整Tab按下/释放最多处理一条。查询回调不能推进队列，实际写入失败或未确认不能当作成功。
- [ ] 复用现有Tab防重复机制，防止长按、系统自动重复、查询/实际双回调造成连续采纳。已接管的Tab键周期不能在提示消失后把剩余重复键漏给宿主。
- [ ] 下一条必须等待本次Tab释放、前一次改文确认及队列重新校验，只有下一次新的Tab按下才能采纳。不得一次按键自动处理多条或批量改文。
- [ ] 提示在某次Tab查询后才出现时，不抢占该次导航键；无可见、有效提示时维持宿主原有Tab行为。
- [ ] 无拼音组合时Esc明确拒绝当前项，将其移出可展示队列并加入短期处理标记；不得立即重查并弹回同一项。
- [ ] Esc拒绝后，不在同一按键周期立刻弹下一项；等Esc释放并出现下一次正常输入机会，再展示下一个有效项。
- [ ] 活动拼音中的Esc先遵循原有取消拼音逻辑，不同时解释为拒绝纠错，不产生错误负反馈。

## 3. P0-2：最短生存期、最长有效期与短词输入

### 时钟定义与优先级

- [ ] 分离去抖、请求超时、建议最长有效期、实际可见时长；不继续让现有捕获started_同时承担所有生命周期含义。
- [ ] 使用单调时钟。建议最长有效期从首次接纳该有效建议开始计算，包含队列等待；初始拟定15秒，到期从队列移除并留下会话内短期处理标记。
- [ ] 最短生存期在产品中解释为“至少展示多久”：从首次实际显示起累计可见时长，后台等待和隐藏时间不算已展示。初始默认3秒，参数仍需可用性验证。
- [ ] 同一建议重复返回、继续普通拼音、相同边界的标点追加不重置创建时间、最长有效期或已累计的可见时间，防止提示永不过期。
- [ ] 用户采纳/明确拒绝可以立即结束；原文/语境失效、无法验证、跨框、关闭纠错、受保护区域等必须立即停用。安全失效和最长有效期优先于最短时间。
- [ ] 出队展示前检查剩余有效时间；不足以提供所选最短展示时间的项不再闪现，按接近到期移除处理。不能通过出队重置最长有效期。
- [ ] 最短时间达到后不强制消失，仍可保留到处理、失效或最长有效期；也不自动将未操作视为拒绝。

### 短词确认后的呈现

- [ ] 同一编辑框正常末尾追加短词时，保留来源仍可验证的有效建议，后台检查追加内容；不要因每次选词上屏无条件清空建议。
- [ ] 仅编辑当前拼音继续保留；修改正文则重新校验。新增内容改变判断语境时撤回或重评，不能只核对错词字面相同就认定仍正确。
- [ ] 候选关闭后，尚需展示的有效提示转到经核对的正文光标旁；下次组合再跟随候选框。复用现有窗口/布局接口，防止出现左上角闪窗或抢焦点。
- [ ] 无可靠锚点时隐藏且不可操作；若同一会话内恢复可靠锚点，仅在最长有效期内恢复，隐藏期间不累计最短可见时长。
- [ ] 提示跟随输入但不遮住候选、正文输入位置，不因长段输入每次候选移动而重复播报或闪烁。

### 用户设置与输入策略参考

- [ ] 复用“管理纠错”的提示设置/预览，新增“最短展示时间”和“最长有效期”，提供单位、说明、合理范围、默认值及恢复默认；输入错误不悄悄保存。
- [ ] 初始拟定最短可选1～10秒、最长可选5～60秒；校验最短不大于最长。参数为起点，不是已验证的人体工学标准。
- [ ] 提供可选预设：“短词频繁确认”建议最短3秒，“长句/长段确认”建议最短5秒；两者最长初值15秒。用户可自由修改，不锁定为两类人。
- [ ] 解释预设依据是确认节奏和阅读机会，不宣称长段用户必然打字更快，也不以缺少来源的统一平均打字速度决定配置。
- [ ] 如提供个性化参考，仅在用户主动启用后，利用本地上屏长度分布、确认间隔等聚合元数据给出建议，样本不足就显示不足；不记录输入正文，不自动改设置。
- [ ] 输入节奏参考与纠错行为学习是不同能力；学习关闭不应被偷偷重新开启，也不借节奏建议改变词典、模型分数或过滤门槛。
- [ ] 新字段沿用现有设置序列化、默认/验证和UI接口。读取旧配置使用明确兼容默认，不能破坏原有选项；配置版本和必要的私有协议字段需同步升级、拒绝不匹配版本。

## 4. P0-3：大量标点、去重与请求调度

- [ ] 保留已验收的模型专用尾部逗号/句号整理，以及严格映射回原文的保护逻辑；不整理正文、剪贴板或实际写回内容。
- [ ] 对等价的自动检查输入进行去重。缓存身份包含模型/配置版本、整理后的target及before/after、来源类型；不能只按“错子”缓存答案。
- [ ] 例如尾部连续相同逗号形成等价视图时合并计算；逗号/句号交错改变最后边界时，不盲目视为等价。仅维持当前已支持的`。，.,`规则，不顺便扩展所有标点。
- [ ] 推理中的等价追加可以合并订阅同一请求，但结果应用时必须核对最新原文/范围并重新映射，不能把旧请求版本直接当作新版本通过。
- [ ] 已有有效结果可在严格相同检查身份、有限有效期内复用，避免每输入一个标点重跑；失败/取消不缓存成“无错”，过期/配置变化后作废。
- [ ] 每个输入会话最多一个在途检查及一个最新待检查快照，旧中间快照被合并，不另建无限请求队列；遵守现有协调器的全局并发边界。
- [ ] 不因每次新上屏都机械取消仍可有用的推理；也不让过时请求堵住最新内容。稳定段结果的接纳以语境及范围重新校验为前提。
- [ ] 去抖之外增加最长调度等待上界，防止一直打字导致永远不检查。初始评估1秒调度上界，仅表示获得调度机会，不承诺1秒内完成模型响应。
- [ ] 增加无正文诊断：去重命中、合并、取消、首次调度、完成与展示时间。分别报告请求数与等待时间，不以总请求减少掩盖漏检。

## 5. P0-4：多个错误按顺序处理

- [ ] 将接口最多8项的返回能力与UI待处理队列区分；初始队列上限5条，包含正在展示的1条，窗口始终只显示一条。
- [ ] 在统一有效性检查后按原文位置先后排序；同位置冲突替换需确定唯一可展示项，重叠建议重评或丢弃，不并列自动执行。
- [ ] 正在展示的项不因新结果分数高就被抢占。新结果插入等待队列，模型自评分不被解释为可靠概率。
- [ ] 队列满时先清过期/失效/重复项，保持当前项和最早的有效待处理项，较后项不继续堆积；记录省略情况，必要时在后续稳定检查补查，不能称为已全部检查。
- [ ] 复用现有锁内来源检查、尾部携带写入、组合保留、写后独立确认和失败不重放流程。队列只安排任务，不成为第二个文本写入通道。
- [ ] 每次成功后维护其余建议的具体范围，处理长度变化，并核对原文及新语境；位置相同不代表仍有效。错误原文不匹配、重叠或身份变化时撤回/重查。
- [ ] 已完成项移除，再按单次按键规则呈现下一项；应用失败不得把该项标为已接受、继续批量尝试或循环自动重试。
- [ ] 提示可显示“还有N处”，N仅指当前已验证队列；不能暗示全文总错误数。更新预览和辅助技术文本。
- [ ] 继续快速打字造成队列更新时，不把淘汰、超时、隐藏、切窗口或未看见当作拒绝；学习关闭时不产生学习写入。

## 6. P0-5：大段输入与有界缓存

- [ ] 区分长拼音尚未确认和大量已确认正文。不能为触发模型强行确认拼音、打断Rime或模拟按键；未确认拼音不冒充已提交文本发送检查。
- [ ] 优先对可验证的稳定上屏段进行有界检查，后续增量合并。一次出现多处错误可逐条排队，不等待整个长段输入结束才允许检查。
- [ ] 复用现有1024 UTF-16单元来源上限与2048写入/验证保护，不因队列直接扩大协议或把全文保存在每条建议里。必要分段应共享有界来源，建议只持有范围和必要元数据。
- [ ] 明确总文本预算、队列5项、一个在途请求加一个最新快照及处理标记容量；达到上限时先移除过期/已处理/不再跟踪内容，保留最近可验证片段，不删除或改动用户正文。
- [ ] 截断不得拆开UTF-16代理对；边界、片段归属和位置无法确认时宁可不提示。被移出捕获窗口的旧建议同步失效，禁止凭字符串在全文中重新搜索并替换。
- [ ] 增量/相邻分段需要防重复和漏掉跨边界错词；如使用有限重叠区，相同范围建议必须合并，并保持正文坐标归属可验证。
- [ ] 连续写入下兼顾较早有效建议与最新检查，不因反复重新检查早段而饿死后段，也不无限保留早段。队列到期后释放其引用。
- [ ] 不扩展为跨文档长期记忆、全文检索或通用长文校对；本轮目标仍是当前可验证邻近输入的及时纠错。

## 7. P0-6：验收矩阵及发布门槛

先补针对生产调用路径的可控时钟/调度测试，再双架构完整回归。人工顺序仍为Off普通输入→Fixed交互→真实冻结4B；实测前明确行为学习关闭。

| 编号 | 场景 | 必须满足 |
| --- | --- | --- |
| T01 | 错句后快速输入并选词“你好”，连续重复短词确认 | 有效提示不会每次提交立即丢失；最短展示可观察、正文及输入正常 |
| T02 | 长拼音/长句一次上屏、组合内退格、删空再输入 | 不强制确认；提示和Tab保留拼音；删正文则旧提示失效 |
| T03 | 一段连续出现2～5处独立错误，含不同位置相同错词 | 按位置逐项展示，不改错位置，不漏掉已入队下一项 |
| T04 | Tab长按、快速连按、查询/实际回调、提示恰在查询后出现 | 一次键周期最多一处；不抢原导航，不重复改文或泄漏重复键 |
| T05 | 无拼音Esc拒绝、重复相同响应；拼音内Esc | 拒绝项不立即回来；下一项不抢同一Esc周期；取消拼音不误判拒绝 |
| T06 | 最短时间未满时继续输入；采纳/拒绝/跨框/源文修改 | 普通输入保留；明确操作可结束；安全失效立即优先 |
| T07 | 排队接近到期、展示时到期、重复响应、新标点追加 | 到期移除、不瞬间复活；不重置最长时钟；不闪现临到期项 |
| T08 | 单逗号、5+逗号、5+句号、三条已验收混合句 | 等价请求合并；非等价正确重查；标点、拼音、实际替换完整 |
| T09 | 修正长度变化、重叠错误、上下文改变语义 | 后续范围重校验，无旧坐标改文或过时判断强行展示 |
| T10 | 6项及以上错误；超来源容量、代理对/分段边界 | 容量有界、淘汰明确；不删正文、不越界、不宣称全文检查完毕 |
| T11 | 快速连续上屏始终短于去抖间隔，夹杂模型慢响应 | 有稳定调度机会、请求不积压；旧结果不回写，输入不阻塞 |
| T12 | 每次纠错后逐步撤销/重做，再继续输入 | 标点/正文/拼音完整，队列不继续使用撤销前范围 |
| T13 | 新设置默认/自选范围/非法值/恢复默认/旧配置 | 保存、取消及迁移语义明确，无不可读设置导致普通输入失效 |
| T14 | Word普通输入、密码/只读、跨框、按应用暂停恢复、搜狗 | 保护边界及日常输入不回归，不开启Word纠错 |

- [ ] 报告固定响应与真实模型分别覆盖的场景、失败证据及修复，不将旧版本通过直接记为新版本通过。
- [ ] 记录捕获→调度→模型→首次可见的分段耗时及提示实际可见时长，验证最短时间与请求去重确实改善体验；不得只展示接口耗时。
- [ ] 成套部署前保留完整回归、独立测试包、占用检测、备份及实际回退演练；不强行结束用户应用，不更改原版输入法。
