## 本轮修正

- 初始化 compartment 监听时，首个注册失败立即返回；cookie 初始化为无效值，失败清理不访问空对象或取消未注册的监听。
- 读取/设置 compartment 数值采用智能指针和明确的错误返回，避免失败后释放未初始化指针；读取失败输出归零。
- 编辑与布局监听分别检查 cookie、分别取消，并同时重置；仅布局监听成功时也能清理。
- 测试窗口改用明确的显示标志，并区分焦点超时与输入失败。初次“没有窗口”与后来的未通过没有进入按键检查；后续有效测试上屏成功。
- 测试程序修正 `GetItem` 返回 `S_FALSE`、对象为空时的检查，避免解引用空对象。
- 候选、语言栏和 compartment 对象的初始 COM 引用采用 `Attach` 接管，避免额外引用泄漏。候选对象不再反向强持有服务；服务销毁时清除其非拥有链接和回调，候选自身持有 DLL 引用，供宿主保留的对象安全返回断开状态。
- 候选 UI 记录是否成功注册，仅配对结束已注册的 UI；停用时在释放线程管理器前结束 UI、销毁窗口并释放候选文档。候选描述字符串每次独立分配，由调用方释放，避免复用已释放的 BSTR。
- 手动探测在必要时重新绑定当前文档，要求编辑监听注册成功；真正读取前再检查当前焦点，防止焦点通知缺失时读取旧文档。
- 诊断增加创建、销毁、激活、停用计数，并将计数相等及 DLL 可卸载加入退出门槛；每次切换要求实际激活次数增加，不能只依赖旧的阶段 100。
- 中文输入回归需要在用户桌面运行。首次工具沙盒中的窗口未被用户看到，未进行输入测试；重新在桌面启动后，用户确认看到“你好”和“测试通过”，程序正常退出。

连续切换复现已细分：原测试每轮关闭宿主窗口，混入了宿主退出过程；改为保留所有测试窗口/文档到测试结束后，同一激活期的三类文档切换通过。`SetFocus` 要传有效文档；切换时恢复到原测试文档，参见 [SetFocus 文档](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfthreadmgr-setfocus)。

完整停用/激活测试仍有间歇失败。诊断中曾连续三轮通过，另有第二或第三次切换失败：`ActivateProfile=S_OK`，实际激活尝试增加两次，最终停在阶段 4，原始结果 `0x80004005`；此时 `GetItem` 仍可能返回已有对象，不能当作新激活成功。失败后对象计数配对、DLL 可卸载，不证明切换已稳定。后续已定位一次失败的直接冲突并加入身份保护，见下一节；完整键盘 TIP 环境与多输入法共存仍须验证。

本测试没有系统级类别注册；`GetProfile` 返回测试配置类别 `GUID_NULL`，`GetActiveProfile(GUID_TFCAT_TIP_KEYBOARD)` 不是测试服务。此环境与安装后的完整键盘 TIP 不同，可能影响切换，但尚未证明它是唯一原因。应在完整隔离安装中验证；不通过更换标准模式项 GUID 绕过问题。

## 语言栏冲突定位与身份保护（2026-10-08 后续）

测试版增加最多 128 条、仅存在内存中的语言栏操作记录，不包含输入正文。复现中，语言栏管理器查询与前一次 `RemoveItem` 均成功，随后 `AddItem` 返回 `E_FAIL`。此时标准模式项属于另一个服务，CLSID 为 `{CC43AF26-60C3-4612-B58D-27A07A40E90B}`。本机 32 位 COM 注册将其命名为 `SogouPY Text Service`，路径为 `C:\Program Files (x86)\SogouInput\16.6.0.4385\SogouTSF.dll`。这确认了本次失败中搜狗模式按钮的冲突；32 位注册信息不能单独证明运行时对象的加载架构，也不能证明旧 v2 故障的唯一根因。

Microsoft 的 [AddItem 文档](https://learn.microsoft.com/en-us/windows/win32/api/ctfutb/nf-ctfutb-itflangbaritemmgr-additem)说明，被忽略的添加也可返回 `S_OK`；[RemoveItem 文档](https://learn.microsoft.com/en-us/windows/win32/api/ctfutb/nf-ctfutb-itflangbaritemmgr-removeitem)说明，移除按项 GUID 识别对象。因此新增以下保护：

- 保存实际执行添加的语言栏管理器；添加成功后通过规范 `IUnknown` 身份确认当前项确属本对象，再显示按钮。
- 停用时再次检查身份。当前 GUID 已属于其他服务或身份查询失败时，不调用移除，避免干扰其他输入法。
- 五种模拟情况全部通过：正常添加/移除、添加失败、成功但被忽略、移除前被替换、移除失败；检查管理器引用归还及其他服务按钮保留。测试入口只在探测构建存在。

最终源码的 `--profile`、`--documents` 与一次 `--cycles` 验证通过。前两者服务对象创建/销毁为 4/4、激活/停用为 7/7；连续切换为 4/4 和 10/10，均可卸载 DLL。桌面 `--input` 日志确认上屏“你好”、候选开始/结束各一次，用户确认窗口提示“测试通过”；计数为 4/4 和 7/7，DLL 可卸载。普通 x64、Win32 TSF 构建通过。短期通过不能证明间歇冲突已全部消失；语言栏注册失败仍会使激活失败，完整共存修复尚未完成。

以下对照未解决问题，相关尝试已撤回源码：对当前传统键盘配置做仅进程停用返回 `E_INVALIDARG`；延迟激活标志没有触发目标测试服务；仅为测试窗口解除传统 IMM 上下文的八组对照中，原路径 8 次通过，解除路径 7 次通过、1 次仍出现同一外部服务冲突。当前没有这些实验开关或对用户输入法的停用逻辑。

## 开始/结束组合状态与延迟旧请求（2026-10-09 后续）

原开始组合会话用默认 `E_FAIL` 返回，实际成功也被报告为失败。现依次检查插入接口、查询范围、组合接口、创建组合、占位文本、折叠范围和选区设置，保留原 HRESULT 并返回最后实际状态。Microsoft [StartComposition](https://learn.microsoft.com/en-us/windows/win32/api/msctf/nf-msctf-itfcontextcomposition-startcomposition) 明确允许宿主拒绝时 `S_OK` 加空组合；本实现将这种拒绝作为无法开始组合的 `E_FAIL` 返回，不解引用空对象。已创建组合之后的设置失败仍保留该真实对象，未假装已回退；自动清理策略留待后续。

结束会话已捕获一个组合，但原显示属性清理和最终状态清空却使用服务当下的组合。现在属性清理明确使用捕获对象，最终清空核对同一对象；迟到的旧 `OnCompositionTerminated` 通知也跳过不匹配的新组合。模拟在旧请求排队后把服务切换为新组合，再执行旧通知和旧请求；检查新范围未查询/修改、新组合未结束且服务状态仍指向新对象。
