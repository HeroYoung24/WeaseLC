## 1. 产品目标与边界

让用户在使用 Weasel 输入时，自愿开启对**当前输入及可获得的邻近文本**的纠错检查，看到有根据、可忽略、可反馈的建议。首版针对错别字、漏字、重复字及明显的搭配错误；不承诺理解任意应用的完整文档，也不自动改写文字。

### 首版原则

- 正常输入优先：模型、网络或纠错界面故障不得阻塞按键、上屏、候选选择和原有设置。
- 建议属于辅助信息，不把模型建议直接插入 Rime 候选首位，也不以“错误”口吻断言不确定的判断。
- 默认关闭纠错；用户明确选择本地或联网模式后才开始分析。联网模式须先说明会发送哪些文本、发送给谁。
- 只处理实际可取得且已获允许的文本；取不到宿主上下文时降级为“仅检查本次输入”，不得暗示已检查整段上文。
- 首版不采集其他输入法的文字、剪贴板或全局键盘记录。不得把 Rime 用户词典当作全文历史。
- 本地学习以可删除的词表、反馈和配置为主；不在用户输入过程中自动更新模型权重。

### 需要优先回答的产品问题

- [ ] 确定目标用户及优先场景：聊天、邮件、长文写作、专业术语输入，分别需要哪些错误类型？
- [ ] 明确“接受建议”的含义：能安全定位原文时替换；无法定位或宿主拒绝编辑时提供复制建议，不假装替换成功。
- [ ] 确定是否支持手动“检查当前输入”入口。建议提供，以便不想持续分析的用户按需使用。
- [ ] 决定用户词典、纠错记忆和模型运行状态是否跨设备同步；建议默认不上传纠错记忆。

- [ ] 依据目标设备评测若干可本地运行的小模型，记录量化版本、许可证、CPU/内存/显存占用、启动时间、P95 延迟和纠错质量；在数据证明有收益后再考虑微调。
- [ ] 把用户常用词、明确保留表达和误判反馈作为抑制/排序特征；Rime 用户词典用于输入习惯，不直接等同于纠错真值。
- [ ] 校准“建议置信度”与“用户词频”两类不同尺度的信号；先保持纠错提示与 Rime 候选分离，经过用户测试后再考虑合并排序。
- [ ] 为每个模型版本定义明确的输出状态：`无建议`、`有建议但不确定`、`可提示的建议`；只有提出了具体修改且通过保护规则与显示阈值时才提示。“模型认为无错”不生成纠错提示。
- [ ] 在独立验证集上检验建议分数与实际正确率的关系，并画出阈值改变时的误报率与漏报率；未经校准的模型自述数字不得作为“80% 正确概率”展示。
- [ ] 对每条建议输出可解释的最小信息：疑似片段、建议文本、可选简短原因和模型/规则来源；限制同一错误重复提示。
- [ ] 采用固定、带版本号的基础模型。用户个性化优先使用本地词表、误判表和阈值；模型升级需通过回归测试，且允许回退。

**P2 通过条件：** 与非模型基线比较，误报、漏报、响应时间有记录；不得仅凭少数演示例子宣布模型可用。

### P3 — 菜单、设置与提示交互

- [x] 本页建议列表、详细原因、手动应用与原生撤销、忽略一次、保留原表达及词表增删清空；动作再次核对当前全文与版本，编辑后失效。三语言资源和双架构真实本地 HTTP 测试通过。该项只覆盖本页手动检查，真实宿主自动提示/替换仍未完成。
- [ ] 下一步优先：正式自动建议进程/IPC与输入后提示；皮肤、尺寸及跟随位置等高级辅助功能后置。

- [x] 实现模型管理和手动检查窗口：本地/联网分别配置，密钥不保存，联网需本次确认，后台单任务、取消和过期结果过滤；敏感度及实验自定义分数可控。提供无网络、无设置持久化的离线演示，Codex CLI 预留且不开放。自动提示时机、皮肤/跟随与宿主替换仍未实现。

- [x] 在托盘菜单及 TSF 语言栏菜单增加“管理纠错”，补齐简体、繁体和英文文案；点击后打开同一设置窗口。现有入口见 [`WeaselServer.rc`](../WeaselServer/WeaselServer.rc)、[`WeaselTSF.rc`](../WeaselTSF/WeaselTSF.rc)、[`WeaselServerApp.cpp`](../WeaselServer/WeaselServerApp.cpp)。尚待安装后手动验证点击路径。
- [ ] 将设置拆成三个概念，避免原“提示强度”的歧义：
  - **运行模式：** 关闭（默认）、本地、联网。显示当前模式、模型是否就绪及联网失败状态；不可用选项写明原因。
  - **提示时机：** 下次在**同一文档/输入场景**开始输入时提示（默认）、检测后立即提示。待提示结果设有效期；文本或光标变化后过期。
  - **检测敏感度：** 保守（建议默认）、标准、积极。敏感度控制阈值，不改变提示时机。
- [ ] **本地也提供个性化入口：** 普通设置让用户选检测敏感度；高级设置仅在当前模型有经过验证的稳定分数时，允许调整“最低提示分数 `x`”，即建议分数低于 `x` 不提示。解释阈值升高会减少提示也可能漏掉错误，并支持一键恢复默认值。
- [ ] 本地、联网模型及其不同版本分别保存阈值；切换或升级模型时验证阈值是否仍有意义，必要时恢复到该模型的默认值并告知用户。不得把某模型的原始分数直接套给另一模型。
- [ ] 将“模型判定无错”与“低置信度”分别处理：前者不生成建议；后者可静默丢弃或按用户阈值过滤。规则检测与模型判断冲突时，先按保守策略抑制提示，再用评测数据确定例外。
- [ ] 增加用户控制：忽略一次、始终忽略该表达、标记误判、暂停当前应用、清除本地学习、手动检查；显示本次检查范围。
- [ ] 提示框自定义：皮肤、尺寸、是否跟随主候选框、相对位置。设置实时预览、恢复默认值，并保证在屏幕边缘及多显示器环境仍可见。
- [ ] 默认提示不抢键盘焦点、不遮挡插入点和候选、不依赖颜色传达含义；对“立即提示”设置节流及同一错误去重。
- [ ] 支持纯键盘操作、屏幕阅读器、高对比度、缩放和触控；设置窗口与建议框有清晰的可访问名称、焦点顺序及关闭方式。
- [ ] 只有在原文、选区和文档版本仍匹配且宿主允许编辑时才执行替换；失败时保留原文并解释原因。确认与宿主撤销/重做行为兼容。

**P3 通过条件：** 用户能在不断开输入流程的情况下发现、查看、忽略或使用建议；切换模式后界面与实际数据流一致。

### P4 — 长文本、多会话及服务化

- [ ] 按模型 tokenizer 计算输入预算，为输出和系统提示预留空间；只送目标句、邻近句及必要的用户词表命中信息。
- [ ] 对长文档分句/段并保留交叠；远处内容按需检索或摘要。实时输入路径不扫描整个文档。
- [ ] 区分模型权重、KV 缓存和产品上下文：模型尽量常驻；缓存可淘汰；需要长期保留的信息进入有期限的用户数据存储。
- [ ] 若提供服务器模式，隔离每个用户的请求、词表、反馈和缓存；限制每人并发与上下文预算。先共享基础模型加用户配置，再评估独立适配器是否值得维护。
- [ ] 记录服务端模型版本、推理配置和请求耗时，不记录原文；设计限流、超时、重试、离线降级与费用上限。

**P4 通过条件：** 超长文本、多窗口及并发用户不会造成输入卡顿、跨用户内容混入或无界内存增长。

- [ ] 测试矩阵覆盖：记事本、Office/富文本、浏览器表单、聊天软件、代码编辑器、终端、密码框；分别记录 TSF 与传统 IME 表现。
- [ ] 覆盖输入边缘行为：组合中/上屏后、选中文本、撤销重做、粘贴、删除、快速连打、焦点切换、输入方案切换、简繁和中英混排。
- [ ] 覆盖显示环境：多屏、屏幕边缘、不同 DPI、全屏、系统深浅色、高对比度、屏幕阅读器。
- [ ] 与原版比较按键响应、候选显示及内存；测量纠错准确率、每千字误报数、建议被采纳率、P95 端到端延迟和用户关闭功能的原因。阈值在原型实测后确定。
- [ ] 让目标用户完成写作任务，观察提示是否打断思路、是否能区分建议与自动修改、是否理解本地/联网状态。

## 3. 易遗漏的场景与预期处理

| 场景 | 预期处理 |
| --- | --- |
| 下一次输入发生在另一个应用、文档或输入框 | 不展示上一场景的待提示结果；按策略清除短期上下文。 |
| 模型返回时原文已编辑或光标已移动 | 丢弃结果或重新检查；不按旧位置替换。 |
| 宿主只暴露部分文本或拒绝只读编辑会话 | 降级为本次输入检查，并向用户准确表述检查范围。 |
| 用户故意输入生僻词、方言、品牌名或专业术语 | 保守提示；支持“这是正确的”和按应用的术语表。 |
| 用户调整本地提示阈值或更换模型 | 立即按新阈值处理后续建议；旧模型分数不跨模型复用；可恢复默认设置。 |
| 密码框、支付字段、疑似敏感内容 | 不分析、不存储、不发送；无法确认时禁用联网路径。 |
| 网络断开、服务启动慢、模型超时或崩溃 | 不阻塞输入；显示简洁状态，避免反复弹错；重试受限。 |
| 文本长于模型窗口 | 检查局部片段，按需分块；不静默截断目标错误及其邻近文字。 |
| 纠错提示与候选框、屏幕阅读器冲突 | 提示不抢焦点，位置可调，可通过键盘读取和关闭。 |
| 多个 Windows 账户或服务器用户 | 词表、反馈、缓存和日志按用户隔离。 |
| 用户关闭功能或删除学习数据 | 停止新请求、清除待处理结果，按说明删除对应本地记录。 |
