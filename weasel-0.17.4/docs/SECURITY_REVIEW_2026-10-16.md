# 安全复查与首次隔离部署准备

日期：2026-10-16。范围：纠错模型接口、自动捕获/写回、子进程、配置/词表、原有 Rime IPC、注册启动及测试包。源码审查和自动回归完成；**目前没有隔离 Windows，未执行真实系统注册或应用验收。** 用户确认先准备测试包和环境方案。

## 发现与处理

| 风险 | 事实及改动 | 已有证据 |
| --- | --- | --- |
| 高：原 IPC 访问面过宽 | 原描述符允许 Everyone 完全访问，未拒绝远程管道连接；改为登录 SID 与 System，保留最小 AppContainer IO 权限，每条消息额外核对登录 SID，拒绝匿名/无法识别客户端和远程连接 | Authz 权限检查、真实自有管道的正常/匿名客户端；跨用户真实登录和 AppContainer 应用仍待客体验证 |
| 高：安全属性未先构造 | 原成员声明中 channel 在 sa 前，构造 channel 时已调用未构造的 sa；调整所有权/顺序，描述符失败时关闭服务创建路径，并释放描述符 | 双架构构建、描述符及句柄释放检查 |
| 高：多客户端共用缓冲区 | 原连接线程并行接收，处理锁之外共用一个缓冲区，可能混入另一应用的数据；改为每连接独立请求/响应缓冲区，保留受锁保护的 Rime API 调用 | 16 客户端并发各 20 次，共 320 次完整元数据及对应响应检查 |
| 高：退出生命周期 | 原连接线程分离，退出没有等待，回调/缓冲区/处理器可能先销毁；改为停止监听、取消 IO、等待连接线程，再销毁处理器；UI 线程等待时仅分派同步发送的窗口消息 | 空闲读、阻塞回复的关闭回收；自有窗口同步回调在退出等待中完成 |
| 中：慢客户端影响其他输入 | 原回复写入/flush 位于全局 Rime 锁内；改为先完成受锁保护的处理，再在锁外发送该连接的回复 | 一个客户端不读回复时，另一个仍能完成请求 |
| 中：元数据范围错误 | 原请求头与正文分开读取后，又按头长度跳过正文开头；标量消息还可能沿用旧缓冲区 | 读取独立有界且 NUL 结束的正文；缺少终止符时在处理前关闭，标量请求清空正文 |
| 中：连接/句柄边界 | 原繁忙连接可无限重试，连接提前完成被误当错误，失败分支遗留句柄 | 连接重试限 1500ms、接受 ERROR_PIPE_CONNECTED、失败关闭句柄；繁忙管道检查通过 |
| 高：客户端身份可被模拟 | 原客户端使用默认模拟身份级别；改为明确 SECURITY_IDENTIFICATION，服务只识别身份，不获客户端执行权限 | 真实自有管道令牌级别检查及身份恢复检查 |
| 部署阻断：工作程序路径 | TSF 安装进系统目录后，原代码仍在 DLL 旁找 Deployer；改为系统安装读取 HKLM 的 WeaselRoot，开发目录保持同目录查找 | x86/x64/大小写/中文空格路径、缺失值与非法路径拒绝；实际安装路径仍待客体验证 |
| 中：子进程搜索路径 | 纠错工作进程继承宿主当前目录；现明确以可信可执行文件的目录作为 CWD，使用完整路径及固定参数，不经过 shell/PATH | 含中文/空格的进程路径及真实模型工作进程回归 |
| 部署阻断：注册假成功 | 原 Setup 等待 regsvr32 后不检查退出码，列表添加失败也可返回成功；现核对等待/退出/列表添加结果并提前停止 | 源码检查、x86 Setup 构建；真实失败回滚仍需快照，不宣称安装具备事务性 |
| 高：提升权限的模块/程序搜索 | 注册程序原用不带路径的 regsvr32，input.dll 也未限制系统搜索；现同线程完整路径 CreateProcess、系统 DLL 搜索，并保留 WOW64 架构选择 | 编译与静态路径检查；真实双架构注册未执行 |
| 中：上游更新覆盖分支 | 开发版仍初始化原版更新器，可能替换实验功能；现关闭自动/手动在线更新执行，界面明确说明当前不提供在线更新 | 最终服务 PE 不再导入 WinSparkle；测试包不携带旧更新器 |

这些等级用于本项目排期，不是 CVSS 分数，也未证明旧问题在这台机器上被实际利用。

管道权限依据：[Microsoft 命名管道访问控制](https://learn.microsoft.com/en-us/windows/win32/ipc/named-pipe-security-and-access-rights)。FILE_GENERIC_WRITE 包含创建管道实例的权限，因此受限包客户端使用明确的 IO 掩码，不能由 AC 授权创建服务端实例。身份校验依据 [ImpersonateNamedPipeClient](https://learn.microsoft.com/en-us/windows/win32/api/namedpipeapi/nf-namedpipeapi-impersonatenamedpipeclient)，身份恢复完成后才进入业务处理。

## 纠错数据与网络复查

- 自动模式默认关闭，只处理该输入法已提交且仍匹配的有界文本，不读取整篇文档；密码/私密/未知字段跳过。设置、焦点、光标、正文或时效改变会取消旧建议。
- 自动模式仅回环本地 HTTP，无代理、无自动认证、无重定向；联网模式仅供显式手动检查，必须 HTTPS 和本次同意。保留词只显式保存在本地，不传给模型；密钥和联网确认不持久保存。
- 请求/响应、JSON 深度、Unicode、偏移、分数与建议数量有界；模型只返回数据，不选择命令、程序或任意写入地址。模型内容即使含指令，也不能执行代码；提示词不能保证模型纠错判断正确。
- Tab 前重新核对原文、范围、文档、光标和类型，只接受同步写锁；无安全写回条件时保留原输入行为。不自动改字，不用模型分数覆盖 Rime 词频。
- 工作进程只继承白名单管道句柄，关闭即回收的 Job 限一个子进程；参数来自固定命令，不开放 Codex CLI。修改后的正式 DLL 不含探测导出。
- 校验普通构建的导入依赖和 TSF 的 ASLR/DEP；除 Windows 自带 DLL 外，程序负载只需随附的对应架构 rime.dll，无额外 MSVC 动态运行库或 WinSparkle 依赖。

宿主提供的输入范围、同登录会话的应用和本地模型服务属于运行信任边界；不能防止宿主错误标注输入类型，也不能承诺已被同一用户恶意程序控制的环境仍保密。本地模型服务不是经过身份认证的多用户服务。

## 旧依赖与发行门槛

源码随附 7-Zip 24.05、curl 8.7.1 和不一致的 WinSparkle 版本。官方 [7-Zip 历史](https://www.7-zip.org/history.txt)记录了后续解压安全修复，官方 [curl 8.7.1 漏洞表](https://curl.se/docs/vuln-8.7.1.html)也列出已知问题。**不能把整个旧安装/下载工具链判为安全。** 本轮测试包不使用这些下载、解压或更新工具，源码 ZIP 也排除两份旧预编译 EXE；Git 原始资产保留，后续公开发行前须更新或移除并验证调用链。

本轮不是所有第三方依赖的完整 CVE/SBOM 审计。测试包不等于可发布安装器；签名、完整对应依赖源码/许可物料、升级/卸载回退、模型质量及真实应用验收仍是发行门槛。
